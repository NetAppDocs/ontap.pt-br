= Crie LIFs ONTAP
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Uma máquina virtual de armazenamento (SVM) fornece dados aos clientes por meio de uma ou mais interfaces lógicas (LIFs), que são endereços IP associados a uma porta física ou lógica. Você deve criar LIFs nas portas que deseja usar para acessar os dados. Se um componente falhar, uma LIF pode realizar failover ou migrar para uma porta física diferente para que continue se comunicando com a rede.

.Antes de começar
* Você deve ser um administrador de cluster para executar esta tarefa.
* A porta de rede física ou lógica subjacente deve estar no status administrativo `up`.


.Sobre esta tarefa
Você pode criar LIFs IPv4 e IPv6 na mesma porta de rede.

.Criando LIFS com sub-redes
* NetApp recomenda criar objetos de sub-rede para todas as LIFs em SVMs de dados. Isso é especialmente importante para configurações do MetroCluster, em que o objeto de sub-rede permite que o ONTAP determine os destinos de failover no cluster de destino, porque cada objeto de sub-rede tem um domínio de broadcast associado. Se você planeja usar um nome de sub-rede para alocar o endereço IP e o valor da máscara de rede para uma LIF, a sub-rede já deve existir. Para obter instruções, consulte link:../networking/create_a_subnet.html["Crie uma sub-rede"].
* Um tráfego entre nós que lida com LIF não deve estar na mesma sub-rede que um tráfego de gerenciamento de manipulação de LIF ou um tráfego de dados de manipulação de LIF.
* Ao criar uma interface de rede entre clusters, você não pode especificar um endereço IP que esteja no intervalo de uma sub-rede existente.
* A partir do ONTAP 9.7, ao criar uma interface de rede com uma sub-rede, o ONTAP seleciona automaticamente um endereço IP da sub-rede selecionada e o atribui à interface de rede. Você pode alterar a sub-rede se houver mais de uma, mas não pode alterar o endereço IP.


.Suporte ao recurso de criação de LIF pela versão do ONTAP
O suporte para recursos relacionados à criação de LIF varia conforme a versão do ONTAP.

[cols="2"]
|===
| Começando com a versão do ONTAP | Recurso 


| 9.12.1 | Suporte para a criação de interfaces de rede para configurações de NFS sobre RDMA no System Manager. Para obter mais informações, consulte xref:../nfs-rdma/configure-lifs-task.html[Configure o LIFS para NFS através do RDMA]. 


| 9.11.1 | Suporte para failover automático de LIFs iSCSI em sistemas All-Flash SAN Array (ASA). Para uma nova LIF iSCSI, o failover é ativado automaticamente com a política  `sfo-partner-only` e a reversão automática definida como  `true` se a SVM não tiver LIFs iSCSI existentes ou se o failover estiver ativado em todas as LIFs iSCSI existentes. Após a atualização para o ONTAP 9.11.1 ou posterior, uma nova LIF iSCSI herda a política de failover  `disabled` se o failover não estiver ativado nas LIFs iSCSI existentes na mesma SVM. Saiba mais sobre link:../san-admin/asa-iscsi-lif-fo-task.html["Failover de LIF iSCSI para plataformas ASA"] 


| 9.10.1 | Os `network interface` comandos incluem um `-rdma-protocols` parâmetro para configurações de NFS sobre RDMA 


| 9,7 | Se já existirem outras LIFs para a SVM na mesma sub-rede, não é necessário especificar a porta inicial da LIF. O ONTAP escolhe automaticamente uma porta aleatória no nó inicial especificado, no mesmo domínio de broadcast das outras LIFs já configuradas na mesma sub-rede. 


| 9,6  a| 
As LIFs usam políticas de serviço para especificar o tipo de tráfego que manipulam. As funções são usadas para especificar o tipo de tráfego no ONTAP 9.5 e em versões anteriores.

.Restrições de criação de LIF
* Não é possível atribuir protocolos nas e SAN ao mesmo LIF.
+
No entanto, protocolos NAS e protocolos SAN baseados em Ethernet podem estar presentes na mesma porta física.

* Um tráfego de gerenciamento de manipulação de LIF deve ser configurado para cada máquina virtual de storage (SVM) que suporte SAN.
* LIFs de NVMe
+
** O protocolo NVMe precisa ser compatível com o adaptador FC no qual o LIF é criado.
** Os LIFs e namespaces NVMe devem ser hospedados no mesmo nó.
** É possível configurar, no máximo, duas LIFs NVMe que manipulam o tráfego de dados por SVM, por nó.
** Uma LIF de dados não pode ser compartilhada entre NVMe e qualquer outro protocolo. NVMe pode ser o único protocolo em LIFs de dados NVMe.
+
Saiba mais sobre link:../nvme/support-limitations.html["Configuração, suporte e limitações do NVMe"].



* LIFs SMB
+
** Não configure LIFs que transportam tráfego SMB para retornarem automaticamente aos seus nós iniciais se o servidor SMB hospedar uma solução para operações sem interrupções com Hyper-V ou SQL Server sobre SMB.




.Passos
Use o System Manager ou a CLI para criar uma LIF.

[role="tabbed-block"]
====
.System Manager
--
.Antes de começar
Se você tiver um grande número de LIFs no seu cluster, poderá verificar a capacidade de LIF suportada pelo cluster antes de criar LIFs adicionais. A partir do ONTAP 9.12.1, você pode visualizar a taxa de transferência na grade Interface de rede no System Manager.

. Selecione *rede > Visão geral > interfaces de rede*.
. image:icon_add.gif["Adicionar ícone"]Selecione .
. Selecione uma das seguintes funções de interface:
+
.. Dados
.. Entre clusters
.. Gerenciamento de SVM


. Selecione o protocolo:
+
.. SMB/CIFS E NFS
.. ISCSI
.. FC
.. NVMe/FC
.. NVMe/TCP


. Nomeie o LIF ou aceite o nome gerado a partir de suas seleções anteriores.
. Aceite o nó inicial ou utilize a lista pendente para selecionar um.
. Se pelo menos uma sub-rede estiver configurada no espaço IPspace do SVM selecionado, a lista suspensa de sub-rede será exibida.
+
.. Se você selecionar uma sub-rede, escolha-a na lista suspensa.
.. Se você continuar sem uma sub-rede, o menu suspenso domínio de broadcast será exibido:
+
... Especifique o endereço IP. Se o endereço IP estiver em uso, aparece uma mensagem de aviso.
... Especifique uma máscara de sub-rede.




. Selecione a porta inicial no domínio de transmissão, automaticamente (recomendado) ou selecionando uma no menu suspenso. O controle de porta inicial é exibido com base no domínio de broadcast ou na seleção de sub-rede.
. Salve a interface de rede.

. Crie um ou mais LIFs nas portas que você deseja usar para acessar dados.
+
[source, cli]
----
network interface create -vserver _SVM_name_ -lif _lif_name_ -service-policy _service_policy_name_ -home-node _node_name_ -home-port port_name {-address _IP_address_ - netmask _Netmask_value_ | -subnet-name _subnet_name_} -firewall- policy _policy_ -auto-revert {true|false}
----
+
** `-home-node` É o nó para o qual o LIF retorna quando o `network interface revert` comando é executado no LIF.
+
Você também pode especificar se o LIF deve reverter automaticamente para o nó inicial e porta inicial com a opção -auto-revert.

+
Saiba mais sobre `network interface revert` o link:https://docs.netapp.com/us-en/ontap-cli/network-interface-revert.html["Referência do comando ONTAP"^]na .

** `-home-port` É a porta física ou lógica para a qual o LIF retorna quando o `network interface revert` comando é executado no LIF.
** Você pode especificar um endereço IP com as opções `-address` `--ip` e `-netmask` `--ip-address`, ou pode habilitar a alocação de uma sub-rede com a opção `-subnet_name` `--subnet`.
** Ao usar uma sub-rede para fornecer o endereço IP e a máscara de rede, se a sub-rede foi definida com um gateway, uma rota padrão para esse gateway é adicionada automaticamente ao SVM quando um LIF é criado usando essa sub-rede.
** Se você atribuir endereços IP manualmente (sem usar uma sub-rede), talvez seja necessário configurar uma rota padrão para um gateway se houver clientes ou controladores de domínio em uma sub-rede IP diferente. Saiba mais sobre `network route create` o link:https://docs.netapp.com/us-en/ontap-cli/network-route-create.html["Referência do comando ONTAP"^]na .
** `-auto-revert` Permite que você especifique se um LIF de dados é automaticamente revertido para seu nó inicial em circunstâncias como inicialização, alterações no status do banco de dados de gerenciamento ou quando a conexão de rede é feita. A configuração padrão é `false`, mas você pode defini-la como `true` dependendo das políticas de gerenciamento de rede em seu ambiente.
**  `-service-policy` A partir do ONTAP 9.5, você pode atribuir uma política de serviço para o LIF com a `-service-policy` opção. Quando uma política de serviço é especificada para um LIF, a política é usada para criar uma função padrão, política de failover e lista de protocolos de dados para o LIF. No ONTAP 9.5, as políticas de serviço são suportadas apenas para serviços de pares entre clusters e BGP. No ONTAP 9.6, você pode criar políticas de serviço para vários serviços de dados e gerenciamento.
** `-data-protocol` Permite criar um LIF compatível com os protocolos FCP ou NVMe/FC. Esta opção não é necessária ao criar um IP LIF.

.Exemplos
O comando a seguir cria um LIF e especifica os valores de endereço IP e máscara de rede usando os `-address` parâmetros e `-netmask`:

+
....
network interface create -vserver vs1.example.com -lif datalif1 -service-policy default-data-files -home-node node-4 -home-port e1c -address 192.0.2.145 -netmask 255.255.255.0 -auto-revert true
....
+
O comando a seguir cria um LIF e atribui valores de endereço IP e máscara de rede da sub-rede especificada (chamado client1_sub):

+
....
network interface create -vserver vs3.example.com -lif datalif3 -service-policy default-data-files -home-node node-3 -home-port e1c -subnet-name client1_sub - auto-revert true
....
+
O comando a seguir cria um LIF NVMe/FC e especifica o `nvme-fc` protocolo de dados:

+
....
network interface create -vserver vs1.example.com -lif datalif1 -data-protocol nvme-fc -home-node node-4 -home-port 1c -address 192.0.2.145 -netmask 255.255.255.0 -auto-revert true
....
