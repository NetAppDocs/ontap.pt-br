[[data-protection]]
== Proteção de dados

[cols="30%,70%"]
|===
| Atualização | Descrição 


 a| 
xref:../data-protection/cloud-backup-with-snapmirror-task.html[SnapMirror com suporte à nuvem para restauração no local no volume de origem original]
 a| 
O SnapMirror cloud oferece suporte a operações de restauração no local para volumes FlexVol, permitindo que você execute uma operação de restauração de snapshot na nuvem diretamente de volta para o volume de origem original. O ONTAP seleciona o snapshot comum mais recente e realiza uma transferência incremental, reduzindo o tempo de restauração.



 a| 
xref:../snapmirror-active-sync/limits-reference.html[Aumento dos limites de objetos da sincronização ativa do SnapMirror]
 a| 
O SnapMirror active sync aumenta o número de volumes compatíveis por par de HA para 600 em configurações SAN e NAS.



 a| 
xref:../snaplock/snapshot-lock-concept.html[Suporte a snapshots à prova de adulteração com SnapMirror active sync NAS]
 a| 
O ONTAP adiciona suporte a snapshots à prova de adulteração com volumes FlexVol NAS do SnapMirror active sync. Este aprimoramento permite que os clientes combinem a disponibilidade do NAS do SnapMirror active sync com a proteção de snapshots imutáveis.



 a| 
xref:../data-protection/modify-svm-dr-dest-vol-capacity-task.html[Recuperação de desastres de SVM aprimorada]
 a| 
O ONTAP aprimora a recuperação de desastres de SVM, permitindo modificar atributos selecionados de volume nos volumes de destino do SVM-DR usando fluxos de trabalho padrão de modificação de volume com privilégio de administrador, reduzindo a necessidade de procedimentos com assistência do suporte.

O ONTAP também estende o suporte opcional ao SVM-DR Quick Resync para os componentes do FlexGroup, ajudando grandes SVMs com FlexGroup a retornarem a um estado protegido mais rapidamente após fluxos de trabalho de ensaio de DR, ressincronização ou inversão de ressincronização.

Para mais informações, consulte xref:../data-protection/resync-svm-destination-task.html[Ressincronize os dados em um SVM de destino do ONTAP SnapMirror].



 a| 
xref:../data-protection/configure-backend-fc-replication.html[Suporte de backend para a replicação do SnapMirror por FC]
 a| 
Você pode configurar a replicação assíncrona de back-end do SnapMirror e o SnapLock for SnapVault em fabrics Fibre Channel (FC) existentes.

Isso permite que o tráfego de replicação trafegue inteiramente dentro da infraestrutura SAN existente. Antes do ONTAP 9.20.1, o tráfego para essas relações de replicação era transportado exclusivamente pela rede IP intercluster.



 a| 
xref:../consistency-groups/protect-task.html[Replicação de um grupo de consistência de origem que não é SnapLock para um grupo de consistência de destino do SnapLock for SnapVault]
 a| 
Você pode replicar de um grupo de consistência de origem sem SnapLock para um grupo de consistência de destino SnapLock for SnapVault. SnapLock for SnapVault protege os grupos de consistência replicados contra exclusão acidental ou maliciosa.



 a| 
xref:../san-admin/fc-sp-3-security-support.html[FC-SP-3 autenticação e criptografia com HBAs seguros da Broadcom]
 a| 
O ONTAP oferece suporte à autenticação e à criptografia do Fibre Channel Security Protocol 3 (FC-SP-3) em HBAs seguros da Broadcom com os sistemas AFF e FAS. O suporte ao FC-SP-3 permite criptografia completamente em nível de hardware e autenticação de dispositivos para proteger os dados em trânsito entre hosts SAN FC e NVMe/FC e os sistemas de storage ONTAP, em conformidade com os padrões de segurança Fibre Channel T11.

A criptografia é descarregada, portanto não há impacto no desempenho do seu sistema de storage.

[[fpolicy-enhancements]]
== Aprimoramentos do FPolicy

[cols="30%,70%"]
|===
| Atualização | Descrição 


 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-nfsv4-concept.html[Suporte do FPolicy para NFS 4.2]
 a| 
O FPolicy estende o monitoramento de acesso a arquivos ao NFSv4.2, possibilitando fluxos de trabalho de auditoria, conformidade e resiliência cibernética para ambientes que usam a versão mais recente do protocolo NFS. O FPolicy gera notificações para operações de arquivo do NFSv4.2, incluindo gravações de atributos estendidos (SETXATTR, REMOVEXATTR) e alterações de rótulos de segurança via SETATTR/GETATTR. As notificações do NFSv4.2 exigem um mecanismo externo configurado com o formato protobuf.



 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-s3.html[Suporte do Fpolicy para storage de objetos S3]
 a| 
O FPolicy oferece monitoramento de segurança para fluxos de trabalho de objetos S3. Isso oferece uma estrutura unificada do FPolicy para arquivos e storage de objetos, simplificando as operações de segurança em ambientes de dados híbridos. O FPolicy para objetos S3 oferece visibilidade do ciclo de vida dos objetos para monitorar a criação e a exclusão de objetos, além de alterações nas tags de metadados, para atender aos requisitos de segurança, conformidade e auditoria. Esse recurso oferece monitoramento não intrusivo sem afetar o desempenho.

[[nas]]
== NAS

[cols="30%,70%"]
|===
| Atualização | Descrição 


 a| 
xref:../smb-admin/supported-versions-functionality-concept.html[Suporte a consultas de nomes normalizados do SMB para clientes Windows]
 a| 
Os clientes Windows podem recuperar nomes canônicos de arquivos e diretórios em uma única solicitação, reduzindo a latência de abertura de arquivos e melhorando a compatibilidade com SMB para desktops, aplicativos e servidores de arquivos corporativos. O ONTAP retorna automaticamente os caminhos canônicos para arquivos e diretórios abertos, evitando pesquisas por componente em clientes Windows 11 24H2 e posteriores, sem necessidade de configuração adicional.



 a| 
xref:../nfs-admin/support-vmware-vstorage-over-nfs-concept.html[Exigência de espaço automática para datastores NFS da VMware]
 a| 
O ONTAP oferece suporte à exigência de espaço automática para datastores NFS por meio do NetApp NFS Plug-in for VMware VAAI. Isso ajuda a recuperar espaço de intervalos de blocos VMDK com thin provisioning quando hosts VMware ESXi 9.0 ou posteriores emitem operações UNMAP.



 a| 
xref:../volumes/cautions-increasing-maximum-directory-size-concept.html[Tamanho máximo do diretório para volumes FlexVol do ONTAP]
 a| 
O ONTAP melhora o desempenho de diretórios muito grandes que contêm até aproximadamente 25 milhões de arquivos, com suporte a tamanhos de diretório de até 4 GB. Os clientes que executam workloads que geram contagens extremamente altas de arquivos em um único diretório, como treinamento de IA, podem se beneficiar ao evitar as penalidades de desempenho observadas anteriormente com diretórios grandes. Ele também melhora a resiliência ao garantir que os diretórios permaneçam totalmente indexados após um failover de proteção de dados, para que as cópias replicadas tenham bom desempenho mesmo quando uma relação do SnapMirror é interrompida. Esse recurso está disponível com os sistemas de storage AFF e FAS, incluindo implantações do MetroCluster; ele pode ser habilitado em cada volume conforme necessário.



 a| 
xref:../task_nas_provide_client_access_with_name_services.html[Suporte para conversão automática de SID para ID UNIX]
 a| 
O ONTAP introduz suporte à conversão automática de SID para ID UNIX em SVMs conectadas ao LDAP para gerar e reverter UIDs/GIDs POSIX a partir de SIDs do Windows. Isso elimina a necessidade de manter manualmente os atributos uidNumber/gidNumber no Active Directory, reduzindo a sobrecarga no gerenciamento e ajudando a garantir acesso a arquivos consistente em NFS e SMB. Esse recurso alinhado aos padrões do setor é especialmente valioso para clientes que migram grandes redes de plataformas NAS baseadas em SSSD e querem preservar a consistência do mapeamento de identidades. O recurso fica desativado por padrão e é configurado por SVM.

[[security]]
== Segurança

[cols="30%,70%"]
|===
| Atualização | Descrição 


 a| 
Enfileiramento justo do Apache para inundações de conexões de gerenciamento e aprimoramentos de pré-cluster
 a| 
O ONTAP introduz o enfileiramento justo por IP de origem, com adesão opcional e desativado por padrão, no servidor web de gerenciamento para ajudar a manter o acesso ao REST, ao System Manager e à ONTAPI durante sobrecargas de conexões de gerenciamento. O ONTAP também oferece suporte à instalação de imagem por meio de uma API REST somente para pré-cluster e aprimora o tratamento do Protocolo de Configuração Dinâmica de Hosts (DHCP) para que a LIF de gerenciamento de nó de pré-cluster permaneça disponível durante as renovações de concessão e as alterações de endereço IP enquanto o nó aguarda a configuração do cluster.



 a| 
xref:../anti-ransomware/modify-snapshot-options-arpai.html[Controles aprimorados para políticas de resposta de instantâneo de ARP/AI]
 a| 
Você pode configurar a política de resposta de snapshots do ARP/AI no nível da SVM ou do volume para controlar se o ARP/AI cria snapshots quando detecta atividade anormal. Há três políticas disponíveis: `alert-with-proactive-and-periodic-snapshot` (padrão, preserva o comportamento existente), `alert-with-proactive-snapshot` (somente snapshots de ataque, sem snapshots periódicos) e `alert-only` (somente alertas e logs de eventos, sem criação de snapshots). Após uma atualização para 9.20.1, a contagem máxima padrão de snapshots periódicos muda de 6 para 2, e o período de retenção padrão muda de 12 para 7 horas, a menos que essas opções no nível do nó tenham sido modificadas anteriormente.



 a| 
xref:../encryption-at-rest/enable-external-key-management-96-later-nve-task.html[Melhorias no fluxo de trabalho de gerenciamento de chaves para SVMs de dados]
 a| 
Ao habilitar um gerenciador de chaves externo em uma SVM de dados, o ONTAP pode migrar automaticamente as chaves de criptografia de volume dessa SVM do gerenciador de chaves com escopo de administrador para o novo gerenciador de chaves da SVM de dados. Isso simplifica a transição para o gerenciamento de chaves externo e elimina a necessidade de uma etapa separada de migração manual no fluxo de trabalho padrão.



 a| 
xref:../multi-admin-verify/index.html[Suporte para grupos do IdP, AD e LDAP como aprovadores do MAV]
 a| 
Os grupos de aprovação do MAV podem incluir o provedor de identidade (IdP), o Active Directory (AD) e grupos LDAP (nsswitch) como aprovadores, além de administradores individuais. Os tipos de grupo compatíveis incluem Entra ID, ADFS, grupos de domínio do AD e grupos LDAP. Adicionar ou remover usuários no diretório do IdP, do AD ou do LDAP não requer nenhuma alteração na configuração do MAV. As alterações na associação de um usuário a um grupo entram em vigor após a reautenticação no próximo login do usuário. Você pode usar o comando security multi-admin-verify registered-operations show para exibir todas as operações disponíveis no cluster atual que podem ser protegidas pelo MAV.



 a| 
xref:../networking/configure_snmpv3_users_in_a_cluster.html[Suporte à autenticação SNMPv3 SHA-512]
 a| 
O ONTAP oferece suporte à autenticação SHA-512 para usuários do SNMPv3. Essa melhoria permite que você use uma autenticação SNMPv3 mais robusta para clientes SNMP externos e para o monitoramento de switches, incluindo switches que exigem autenticação SHA-512. Para obter mais informações, consulte Configure SNMPv3 users in an ONTAP cluster e Configure SNMPv3 for Ethernet switch health monitoring.

Para mais informações, consulte https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["Configurar o SNMPv3 para monitoramento da integridade do switch de rede Ethernet"].

[[storage-efficiency-enhancements]]
== Melhorias na eficiência de storage

[cols="30%,70%"]
|===
| Atualização | Descrição 


 a| 
xref:../concepts/capacity-measurements.html[Relatórios simplificados das taxas de redução de dados da eficiência de storage]
 a| 
A taxa de redução de dados (DRR) da eficiência de storage fornece uma avaliação mais precisa da economia de espaço da eficiência de storage do ONTAP ao incluir apenas dados redutíveis. No ONTAP 9.19.1 e em versões anteriores, a DRR inclui dados redutíveis e não redutíveis.



 a| 
xref:../concepts/builtin-storage-efficiency-concept.html[Melhoria de desempenho após a migração de volumes de sistemas não QAT para sistemas QAT]
 a| 
O ONTAP reduz a latência de leitura adicional e o uso da CPU que podem ocorrer após a migração de volumes de sistemas que não suportam a tecnologia QuickAssist (QAT) para sistemas que a suportam.



 a| 
Otimização do Agendador Automático de Desduplicação (ADS)
 a| 
O ONTAP aprimora o desempenho do ADS (Automatic Dedupe Scheduler), permitindo mais sessões simultâneas de deduplicação por nó, além de uma limitação mais inteligente e direcionada para equilibrar melhor a E/S do cliente. A atividade de deduplicação em volumes DP (de transferências do SnapMirror) e as sessões de Deduplicação Global são gerenciadas junto com a deduplicação regular de volumes, o que reduz a contenção e o crescimento dos metadados. Você pode se beneficiar da economia de eficiência de storage, especialmente em workloads mistos, sem necessidade de alterações de configuração. Esse recurso está habilitado por padrão e está disponível em sistemas de storage AFF.

Os administradores podem agendar a exclusão de buckets que contêm objetos ao usar uma janela de recuperação configurável baseada em retenção.  a| 
xref:../flexcache/sizing-concept.html[FlexCache aumenta os limites de dimensionamento]

 a| 
xref:../flexcache/supported-unsupported-features-concept.html[Suporte a NVFail com FlexCache]
 a| 
Você pode criar relacionamentos do FlexCache com origens com NVFAIL habilitado. Você também pode habilitar o NVFAIL em volumes de cache, independentemente dos volumes de origem. Em volumes de origem ou de cache em que ocorreu NVFAIL, o ONTAP bloqueia leituras de dados ou modificações, enquanto preserva o write-back de dados em cache modificados, e a E/S normal é retomada após a recuperação.



 a| 
Melhoria de desempenho para exclusão assíncrona
 a| 
O ONTAP aprimora o desempenho da exclusão assíncrona e acelera a exigência de espaço para clientes NAS/SMB. Entre em contato com seu representante da NetApp para obter detalhes.



 a| 
xref:../data-protection/calculate-reclaimable-space-task.html[Suporte para o cálculo do espaço recuperável em volumes FlexGroup]
 a| 
O ONTAP oferece suporte ao recálculo do espaço recuperável antes de excluir o snapshot em volumes FlexGroup.



 a| 
xref:../flexgroup/provision-automatically-task.html[Provisionamento automático de volumes FlexGroup de alto desempenho]
 a| 
O ONTAP simplifica o provisionamento do FlexGroup com perfis de armazenamento que permitem aos clientes escolher um contêiner de dados equilibrado ou de alto desempenho para suas cargas de trabalho, reduzindo a necessidade de os administradores configurarem e dimensionarem manualmente os volumes constituintes para atender aos requisitos de desempenho.



 a| 
xref:../flexgroup/enable-adv-capacity-flexgroup-task.html[Suporte a multicanal SMB com rebalanceamento avançado de capacidade]
 a| 
O ONTAP oferece suporte ao uso de SMB Multichannel quando o balanceamento avançado de capacidade está habilitado em volumes FlexGroup.



 a| 
xref:../svm-migrate/index.html#supported-and-unsupported-features[Suporte à migração de SVM para buckets NAS S3]
 a| 
O ONTAP oferece suporte à migração de SVMs que hospedam buckets S3 NAS em volumes FlexVol, permitindo que os administradores migrem SVMs sem precisar remover primeiro a configuração do S3 NAS.



 a| 
xref:../task_nas_file_system_analytics_view.html[Preservação do tempo de acesso do File System Analytics]
 a| 
O File System Analytics e a navegação no File System Explorer do System Manager preservam os metadados de hora de acesso ao diretório (atime). Isso ajuda a manter valores de atime precisos para fluxos de trabalho de arquivamento, hierarquização, conformidade e ciclo de vida dos dados.



 a| 
xref:../volumes/manage-svm-capacity.html[Suporte IP do MetroCluster para limites de capacidade de SVM do ONTAP]
 a| 
É possível configurar limites de armazenamento para SVMs que fazem parte de uma configuração IP do MetroCluster.



 a| 
FlexCache Métricas de volume
 a| 
As métricas de volume do FlexCache informam a quantidade de dados e metadados trocados entre um volume do FlexCache e seu volume de origem. Duas novas propriedades foram adicionadas aos endpoints existentes de estatísticas e métricas de volume da API REST do ONTAP que fornecem visibilidade da transferência de dados do FlexCache para a origem e da origem para o FlexCache. Os contadores são coletados automaticamente, sem necessidade de configuração; eles são úteis para planejamento de capacidade, análise de desempenho, solução de problemas de rede e análise de chargeback. Esse recurso requer o ONTAP 9.20 ou posterior nos nós do FlexCache e de origem. Consulte a documentação link:https://docs.netapp.com/us-en/ontap-automation["Automação ONTAP"^] para obter mais informações.



 a| 
Reequilíbrio intracluster
 a| 
O ONTAP introduz dois novos recursos de Balanced Placement para ajudar a manter os clusters com desempenho ideal, com mínimo esforço administrativo, à medida que suas cargas de trabalho e a capacidade do cluster evoluem. O controle de posicionamento no momento do provisionamento permite que os clientes indiquem se os requisitos de desempenho ou de espaço devem ser priorizados quando um novo volume é colocado por meio da API REST. O Space Performance Rebalance (SPR) é um processo em segundo plano que busca continuamente possíveis pontos críticos de desempenho ou pressão de espaço em agregados em todo o cluster. Dependendo do modo configurado, o SPR recomenda movimentações corretivas de volumes por meio de notificações do EMS ou executa as movimentações automaticamente usando operações padrão e não disruptivas de movimentação de volumes do ONTAP. Consulte a link:https://docs.netapp.com/us-en/ontap-automation["Automação ONTAP"^] documentação para obter mais informações.

xref:../task_cp_dashboard_tour.html[Alertas aprimorados para expiração de certificados e senhas de usuários]

O System Manager exibe um alerta de integridade no painel 30 dias antes do vencimento do certificado de um cluster ou de uma máquina virtual de armazenamento (SVM) e o atualiza diariamente com os dias restantes até o vencimento. As configurações do cluster também podem ser definidas para que os usuários locais recebam um banner na parte superior da página após fazer login, a partir de 14 dias antes do vencimento da senha.
